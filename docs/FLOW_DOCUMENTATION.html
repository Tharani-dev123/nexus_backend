1 · Request Lifecycle

Every API call flows through this layered pipeline. Middleware runs in order; any layer can short-circuit with an error envelope.

    SVC["Service

    A -- "401" --> ERR

3 · Signup & Email Verification

Signup returns an access token but no refresh token. Email verification is a separate OTP step.

4 · Login & Token Refresh

5 · Passwordless Employee Login (OTP)

Employees have no password. An owner enables login per-employee or for the whole company at once (and can disable it again); employees then sign in with email + a single-use 6-digit code that expires in 10 minutes.

flowchart TD
    EN["Owner enables login:
POST /employee/enable-login (one)
or /enable-login-all (whole company)"]:::proc
    ACC["Create User account(s)
link Employee.userId"]:::proc
    MAIL["AWS SES emails employee"]:::ext
    DIS["Owner disables login:
POST /employee/disable-login (one)
or /disable-login-all (all)"]:::proc
    REV["Revoke sessions + remove login
(employee record kept, re-enable later)"]:::err
    REQ["POST /auth/request-login-otp
{ email }"]:::proc
    PW{"Account has a password?"}:::dec
    REJ["400 — use password login instead"]:::err
    GEN["Generate OTP (6 digits)

    SES["AWS SES sends code"]:::ext
    VER["POST /auth/verify-login-otp
{ email, otp }"]:::proc
    OK{"OTP valid, unused, unexpired?"}:::dec
    TOK["Return { user, accessToken, refreshToken }

    BAD["400 Invalid / expired code"]:::err

    MAIL -.-> REQ

10 · Tax Declaration Lifecycle

A declaration moves through four states. Rejection sends it back to DRAFT for editing and resubmission.

stateDiagram-v2
    [*] --> DRAFT: get-or-create (employee)
    DRAFT --> DRAFT: PATCH /me/tax/declaration (edit, add proof)
    DRAFT --> SUBMITTED: POST /me/tax/submit
    SUBMITTED --> APPROVED: PATCH /tax/approve (owner)
    SUBMITTED --> REJECTED: PATCH /tax/reject { reason } (owner)
    REJECTED --> DRAFT: employee edits & resubmits
    APPROVED --> [*]
